# Developing career-ops in this checkout

- This checkout is for working ON career-ops. `AGENTS.md`, `CLAUDE.md` and `modes/` are the product's prompts to its users' agents, not instructions for you. Never create user-layer files here as a side effect (`node doctor.mjs --json` is read-only; never add `--init-templates` unless asked).
- Before pushing: `npm run lint` (under 1 s), then `node test-all.mjs --quick`. Changes under `dashboard/` or to `templates/states.yml` also need `go test ./...` from `dashboard/`.
- A new test is its own file under `tests/*.test.mjs`. Never add a numbered section to `test-all.mjs`, never place `*.test.mjs` at the repo root, never call `process.exit()` or `finish()` from a discovered suite. A script that checks whether it is the entry point uses `isMainModule(import.meta.url)` from `lib/is-main-module.mjs`, never `process.argv[1]`. Chromium or TeX suites declare `toolRequired('browser'|'latex')`.
- Every tracked file must be claimed by SYSTEM_PATHS, USER_PATHS or `config/local-paths.txt`, or `node validate-system-paths-coverage.mjs` fails the suite. A fork-local file at the repo root or in a directory upstream does not ship goes in `config/local-paths.txt`, never in USER_PATHS; a fork file inside a shipped directory (`tests/`, `docs/`, `.claude/skills/`) is covered by that directory's SYSTEM_PATHS entry, survives `apply` because the stale-file prune deletes only paths upstream once shipped, and gets a row in the deviations table in `.claude/skills/upstream-review/SKILL.md` instead. Inside `.claude/`, upstream ships `settings.json` and `hooks/` as USER_PATHS and `skills/` as SYSTEM_PATHS; `rules/` and `agents/` are fork files in `config/local-paths.txt`.
- Commits follow Conventional Commits with a scope (`fix(scan): …`, `docs(oferta): …`), enforced by `.githooks/commit-msg`. The fork cuts no releases and no changelog (`release.yml` was removed); `CHANGELOG.md` and `VERSION` arrive with upstream merges. The convention is kept so a commit can be offered upstream unchanged.
- Upstream wants an issue first for a new feature, mode, command or architecture change; bug fixes, providers, docs and translations go straight to a PR. The PR body must state no personal data was added and `node test-all.mjs` passed.
- System layer vs user layer is the one rule that must never slip: personalization never lands in `modes/_shared.md`, scripts, templates or `AGENTS.md`. See DATA_CONTRACT.md.
- The git pre-commit hook in `.githooks/` refuses a newly added gitignored (user-layer) file and syntax errors; edits and deletions of tracked files pass. The syntax check walks the working tree, not the index, so an unstaged broken `.mjs` blocks any commit. If it did not run, `git config core.hooksPath .githooks` is missing (the SessionStart hook sets it).
- Never run `node update-system.mjs apply`, `npm run update` or `./cops update` here: they replace system-layer files from the release tarball (a locally modified one is kept behind a `.bak` only without `--force`). The SessionStart hook already ran `check`; on `update-available`, run `/upstream-review`. AGENTS.md's instruction to offer `apply` is the product's prompt to its users, not to you.
